# Choosing a small Amharic distillation student

Research date: 2026-11-22. **Keep `rasyosef/Llama-3.2-1B-Amharic-Instruct` as the primary cost-sensitive candidate, and evaluate it against Gemma 4 E2B before selecting a winner.** Its Amharic tokenizer advantage is measured; its chatbot quality advantage is not established. The existing two-model training protocol remains appropriate.

Public model metadata and cards were checked for 26 checkpoints, including Amharic instruction models, newer Qwen fine-tunes, Tiny Aya, and Amharic vocabulary-trimmed Gemma models. Discovery used both model-name searches and the `am` language tag; this is a focused search, not an exhaustive model census. Exact revisions, source URLs, file hashes and download limitations are recorded in the [research results](../experiments/student_tokenizer_research_2026-11-22.json). The one-off research script was removed at the user's request after retaining these results.

The strongest reason for the Llama candidate is its adaptation history. Its [base model card](https://huggingface.co/rasyosef/Llama-3.2-1B-Amharic/blob/7bbb1206a4efa603e558d312514a8ec60014ad12/README.md) reports adding approximately 16K Amharic tokens and continuing pretraining on 300 million Amharic tokens. The [instruction model card](https://huggingface.co/rasyosef/Llama-3.2-1B-Amharic-Instruct/blob/354e5403992da727615164b975594cde4529ab94/README.md) supplies an inference example, but no benchmark table or detailed instruction-training recipe. The checkpoint contains approximately 1.27B parameters. Comparing its vocabulary with the public Unsloth mirror of stock Llama 3.2 found 15,122 additional vocabulary entries, with every original token ID preserved. Its embedding dimension is padded to 143,424 entries; the tokenizer dictionary has 143,378 entries.

Tokenization was measured on all **4,952 current training conversations**, containing 9,904 messages. Of these, **8,805 messages / 485,366 whitespace-separated words** are Amharic-dominant: at least 70% of their letters have Ethiopic Unicode names. Every model sees the same text. Each message is encoded independently with `add_special_tokens=False`; there is no chat template, truncation, padding or extra normalization. The tokenizer's own normalization remains active. No held-out evaluation text was used.

“Tokens per word” is a corpus ratio using whitespace, not a linguistic word segmentation or a claim that every word splits equally. For example, isolated `አመሰግናለሁ` uses 2 tokens with Amharic Llama 1B, 6 with Gemma 4 E2B, 8 with Qwen 2.5/3, and 11 with Qwen 3.5. With a preceding space the counts are 1, 5, 10 and 11. Real sentence measurements matter more than isolated examples.

Across the complete training text, Amharic Llama 1B uses **42.3% fewer content tokens than Gemma 4 E2B**, **70.9% fewer than Qwen 2.5/3**, and **73.5% fewer than Qwen 3.5**. These are token savings, not measured training-cost or latency reductions. Model architecture, quantization, padding, output vocabulary and hardware also affect cost. The 400M model compresses Amharic slightly better but uses more tokens overall on this mixed-language workload.

Content alone exceeds 2,048 tokens in 33 conversations with Qwen 2.5/3 and 49 with Qwen 3.5; none exceed it with the Amharic Llama or measured Gemma tokenizers. Chat templates add overhead, so these are lower bounds for training lengths. Use the existing reviewed-data tokenizer preflight for the actual training gate. All measured shortlist tokenizers round-trip the training messages exactly. The separate 51.8M Amharic research/GEC models score about 1.75 tokens per word, but their NFKC tokenizer changes 40 messages on round-trip and their task/capacity are unsuitable for the intended general chatbot.

Other findings narrow the search. The Gemma 3 1B/32K trimmed checkpoint currently publishes no tokenizer files; its reduced embedding vocabulary cannot safely use an arbitrary original tokenizer. The tested Phi checkpoint has a very expensive Amharic tokenizer and a sparse model card. Walia has an [EMNLP paper](https://aclanthology.org/2024.findings-emnlp.25/) and task-specific evaluation, but the inspected Walia-II checkpoint is a larger Llama-2-based model. An `afrisynt` checkpoint whose name ends in `Llama-3.2-1B-Instruct` actually has an approximately 8B Llama configuration and stored tensor count. Names and language tags require verification.

The Amharic Llama cards do not declare a standalone license; check the inherited Meta Llama 3.2 license and applicable terms before deployment. This differs from Gemma 4's Apache 2.0 terms and Gemma 3's Gemma terms. Model adaptation does not remove upstream obligations.

The recommendation is provisional on answer quality. Run the existing unchanged/adapted Llama and unchanged/adapted Gemma comparison on the same frozen data, then use blind native-speaker correctness, fluency and instruction-following scores, category results, repetition/truncation, peak RAM/VRAM and **words or characters per second** alongside tokens per second. Compare perplexity only within each model/tokenizer pair. A common output-token cap allows different amounts of visible text across tokenizers; report cap hits when interpreting comparisons. No GPU training, model inference, human scoring or speed benchmark was performed for this research.

For the research task, the defensible selection statement is: **“I chose Llama-3.2-1B-Amharic-Instruct for the first distillation experiment because it combines Amharic continued pretraining and instruction tuning with a measured tokenizer advantage on our target data. Gemma 4 E2B remains the quality comparator; final selection depends on held-out Amharic quality and deployment measurements.”**
